一、我（原環境）是什麼、有哪些能力

原環境是 Anthropic Claude Code 的雲端沙盒：一個隔離的 Linux 容器，repo 開機時 clone 好，對外網路走受控 proxy。接手方要知道原環境「靠什麼做到現在的品質」，才能在新環境補齊等價能力。

三、不可改壞的鐵則（完整版在 CLAUDE.md，這裡是摘要）

  • drawCreature(c, kind, x, y, s, o) 簽名不可改；8 個基本 kind（leopard/bear/cicada/dragonfly/snail/iguana/frog/ibis）都要支援；o 既有欄位語意不可改。
  • 資料結構 HEROES[] / CH[] / TYPE / ADV / eff() 欄位不可刪改名；屬性相剋 🌲>💧>🌪>🪲>🌲 不可動。
  • 零外部依賴：不可用 CDN／外部 script／外部字型。美術「圖檔優先＋canvas fallback」，圖檔一律 repo 內本地檔並加入 sw.js ASSETS。
  • 輸入一律 Pointer Events ＋ preventDefault ＋ {passive:false}；dock 按鈕 id bLeft/bRight/bSwap/bJump/bSp/bAtk 不可改名。
  • 進度鍵 localStorage["shoutu_unlocked"] 不可改名（其他存檔鍵清單見 docs/ARCHITECTURE.md）。
  • 粒子/特效必須有硬上限＋回收，禁止每幀無上限 push。
  • 改任何會被快取的檔案（index.html/src/assets），sw.js 的 CACHE 版本號必須 +1（目前 shoutu-v138），否則舊玩家永遠拿不到新版。

四、標準工作流程（每次改動都走這套）

# 0. 取得程式碼
git clone https://github.com/jimmyliao/maxgame.git
cd maxgame && git checkout claude/dinosaur-game-infinite-levels-kpfmbm
npm install   # 只有測試需要；遊戲本體零依賴

# 1. 驗收一票否決項（改完必跑，任一失敗不得部署）
sed -n '/<script>/,/<\/script>/p' index.html | sed '1d;$d' > /tmp/game.js && node --check /tmp/game.js
for f in src/*.js; do node --check "$f"; done
npm run typecheck && npm run test:unit && npm run test:smoke

# 2. 版本號（有改快取檔案時）
#    sw.js 第 2 行 CACHE 版本 +1；新圖檔加入 ASSETS 清單

# 3. 更新文件：CLAUDE.md「目前狀態」補一條本次變更（含 sw 版本）

# 4. 部署（同一 commit 推兩條分支）
git add -A && git commit -m "變更摘要 (sw vNNN)"    # commit 訊息用繁體中文
git push -u origin claude/dinosaur-game-infinite-levels-kpfmbm
git checkout main && git pull origin main
git merge --ff-only claude/dinosaur-game-infinite-levels-kpfmbm
git push origin main
git checkout claude/dinosaur-game-infinite-levels-kpfmbm

# 5. 確認 CI 綠燈（push 自動觸發），Pages 1–2 分鐘後更新

五、新環境接手前的驗證清單（照順序做完才算接手成功）

  1. 讀取驗證：能讀 CLAUDE.md、docs/SPEC.md、docs/ARCHITECTURE.md、docs/SESSION-NOTES-20260716.md（上次 session 詳細紀錄）。
  2. 環境驗證：Node ≥ 20（原環境 v22）、npm install 成功、Playwright Chromium 裝得起來（npx playwright install chromium）。
  3. 測試驗證：上面第 1 步全綠——特別是 test:smoke 必須 1 passed。這證明新環境有跟原環境同級的驗收能力。
  4. 寫入驗證：對開發分支推一個無害 commit（例如 docs 加一行），確認 push 權限正常。
  5. 部署驗證：ff-merge 到 main 並 push，1–2 分鐘後檢查： 
    curl -s https://jimmyliao.github.io/maxgame/sw.js | head -3   # 應看到目前 CACHE 版本
  6. CI 驗證：確認該 commit 的 GitHub Actions「CI」workflow 綠燈。
  7. 回報使用者：以上全過，回報「接手驗證完成」＋目前 sw 版本，再開始接任務。

六、給 Discord bot 型 agent 的特別提醒

  • 互動模式差異：原環境是「使用者一句話 → agent 自主做完整條流程（改碼→測試→部署→回報）」。Discord 訊息較零碎，建議維持同樣紀律：動手前把理解寫成一句需求確認，做完回報「改了什麼＋sw 版本＋已部署」。
  • 使用者是家長＋小孩玩家群：溝通用繁體中文、口語、直接。產品文案標準見 CLAUDE.md v137 那條（去 AI 味、去公文腔、像 2022–2026 小孩遊戲的語感）。
  • 長流程要可中斷續作：原環境靠「每步都 commit push」保工作不丟失。bot 環境若會被重啟，同樣要小步提交。
  • 祕密管理：bot 的 API key、git token 走環境變數，絕不進這個 public repo；不在 Discord 頻道貼任何金鑰。
  • 需要使用者親手做的事（agent 只能準備內容）：Firebase Console 貼規則、Play Console 填表上傳、真機測多人連線、保管 keystore。
