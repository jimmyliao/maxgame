## 1. Juice 手感檢核清單（對照守土現況）

> **Juice 的定義**（Petri Purho）：讓玩家「用很小的輸入，得到遠超過其應得的輸出回饋」。它**不改遊戲規則，只改感受**。
> **Vlambeer 核心心法**（Jan Willem Nijman《The Art of Screenshake》）：一個「無聊」的射擊遊戲，靠 ~30 個微小 tweak 疊加，就能脫胎換骨。**每一項都便宜，疊起來才是靈魂。**
> 下表把業界手感技法逐條列出，對照守土**已達 / 可加強 / 缺**。標記依 CLAUDE.md 與 SYSTEMS.md 現況推斷。

### 1.1 命中回饋（Impact / Hit feedback）

| # | 技法 | 為什麼有效 | 守土現況 |
|---|---|---|---|
| J-01 | **Hit-stop（命中定格 / sleep）**：命中瞬間全遊戲凍結 3~5 幀 | 給大腦「登記」這一擊的時間，重量感來源 | **已達**（重擊/必殺/首領震波/擊破皆有 hit-stop） |
| J-02 | **傷害浮字（damage float）**：命中數字往上飄+淡出 | 量化回饋、爽感可讀 | **已達** |
| J-03 | **命中火花 / 撞擊粒子** | 視覺確認「打中了」 | **已達**（命中火花） |
| J-04 | **敵人受擊動畫（hit flash / 白閃 / 縮放）**：被打的入侵種閃白或被壓扁一下 | 受擊方也要有反應，不能只有攻擊方 | **可加強**（確認入侵種是否有受擊白閃 / squash；建議補） |
| J-05 | **擊退 / 擊飛（knockback）**：命中把敵人往後推 | 力的傳遞，讓打擊「有重量」 | **可加強**（首領/衝撞有位移；一般命中的微擊退可補） |
| J-06 | **連擊回饋（combo escalation）**：連段越高、音效音高越高、字越大 | 正回饋螺旋，鼓勵連段 | **可加強**（有 comboBest 顯示，缺「即時升階的音畫放大」） |

### 1.2 攻擊者側回饋（預期＋跟隨）

| # | 技法 | 為什麼有效 | 守土現況 |
|---|---|---|---|
| J-07 | **Anticipation（預期動作 / 蓄力）**：出招前有一個「往後拉」的預備幀 | 讓招式可讀、可預判、有節奏 | **可加強**（首領蓄力衝撞有；守護者普攻/技能的出手前搖可補一格） |
| J-08 | **Follow-through（跟隨 / 收招慣性）**：出招後身體慣性收尾、後坐力 | 動作不「斷」，有生命感 | **可加強** |
| J-09 | **後坐力 / 反衝（recoil / kickback）**：出手瞬間自己微微後退或槍口上抬 | 力的反作用，讓輸出「有勁」 | **可加強**（近戰可做「出手瞬間角色前衝一點點再回位」的 lunge） |
| J-10 | **武器/招式的「大一點、快一點」**：投射物/命中框視覺放大、攻速給足 | Vlambeer 名言：子彈畫大三倍就是爽 | **可加強**（技能特效可放大；不改判定數值，只放大視覺） |

### 1.3 鏡頭（Camera）

| # | 技法 | 為什麼有效 | 守土現況 |
|---|---|---|---|
| J-11 | **Screen shake（螢幕震動）**：大事件時鏡頭抖動 | 「震動空氣與大地」的事件才配抖 | **已達**（螢幕震動） |
| J-12 | **震動要「稀有而猛烈」+ 快速衰減**：0.1~0.3s、隨機方向、easing 收尾 | 到處抖=沒感覺；克制才有力 | **可加強**（確認是否分級：普攻小抖、必殺中抖、首領擊破大抖；建議分 3 級 amplitude） |
| J-13 | **鏡頭跟隨 / 前瞻（look-ahead）**：鏡頭往移動/瞄準方向偏一點 | 給視野、給速度感 | **已達**（跟隨鏡頭；look-ahead 可加強） |
| J-14 | **命中定格時的鏡頭微推（punch-in zoom）**：hit-stop 同時鏡頭猛推 1~2% 再回 | 放大「這一擊很重」 | **可加強**（首領擊破可加 punch-in） |
| J-15 | **電影運鏡（letterbox / 掃光 / 名號滑入）** | 儀式感、事件的份量 | **已達**（首領登場運鏡已達 Supercell 水準） |

### 1.4 音畫同步與節奏（Audio / Rhythm）

| # | 技法 | 為什麼有效 | 守土現況 |
|---|---|---|---|
| J-16 | **每個動作配音效**：攻擊/命中/受擊/撿拾/按鈕 | 聽覺是手感的一半 | **已達**（`src/sfx.js` 程序化 Web Audio 全覆蓋） |
| J-17 | **音高/音量隨機化（±5~15%）**：同一音效每次略不同 | 避免重複疲勞，聽起來「活」 | **可加強**（確認 sfx.js 是否對重複音做 pitch jitter；建議補） |
| J-18 | **音畫同幀（命中的視覺與聲音同一幀觸發）** | 不同步會「軟掉」 | **已達**（同觸發點） |
| J-19 | **上升式音階回饋（combo / count-up 越高音越高）** | 情緒往上堆 | **缺**（結算/連段可加音階遞升） |

### 1.5 恆存與粒子（Permanence / Particles）

| # | 技法 | 為什麼有效 | 守土現況 |
|---|---|---|---|
| J-20 | **Permanence（痕跡恆存）**：擊敗的敵人留下短暫殘影/污漬/落葉、棲地由枯轉綠 | 玩家「看得到自己造成的改變」＝守護感 | **可加強**（棲地復原度有；戰場「擊敗留痕」可補，扣宗旨「棲地復原」） |
| J-21 | **粒子噴發（碎屑/煙/落葉）** | 事件的份量、生命感 | **已達**（有粒子；**鐵則：硬上限+回收**） |
| J-22 | **拖尾（trail）**：投射物/衝刺留尾 | 速度與軌跡可讀 | **可加強** |
| J-23 | **物件反應環境**：擊中會晃動的草叢/水花 | 世界「活著」、有互動感 | **可加強**（棲地地形互動，交 canvas-techniques） |

### 1.6 UI 手感（Juicy UI）

| # | 技法 | 為什麼有效 | 守土現況 |
|---|---|---|---|
| J-24 | **按鈕 squash & stretch（按下縮、放開彈）** | 觸控回饋、活潑 | **可加強**（大廳鈕彈性，見 R-BS-06） |
| J-25 | **數字 count-up（逐格跳，不瞬間到位）** | 期待感、爽點延展 | **可加強**（票券飛入有；保育值/XP 逐格跳見 R-BS-01/R-FEEL-03） |
| J-26 | **可領提示紅點/彈跳** | 引導、召回 | **缺**（見 R-BS-06） |
| J-27 | **進度條充能動畫 + 里程碑閃光** | 目標可視化、差一點就到 | **缺**（見 R-FEEL-03） |

### 1.7 手感總結：守土的「三缺口」

1. **受擊方回饋不足**（J-04/J-05）：攻擊方 juice 很飽，但入侵種被打的「白閃/壓扁/微擊退」可補，打擊才「雙向」。
2. **預期/跟隨動作偏少**（J-07~J-09）：守護者招式可加一格前搖與收招慣性，讓動作「有起有落」。
3. **獎勵/UI 揭曉的 juice 幾乎全缺**（J-25~J-27）：這是**本文重點與最高 CP 值**，見 §2、§3。

## 2. 獎勵揭曉演出設計（深化 R-BS-01）

> **核心心理學**：**期待 > 獲得**。多巴胺在「即將得到、還沒得到」時最高。把「領獎」從「一次塞數字」改成**有節奏、有懸念、有爽點的小演出**，是留存與「再來一場」的引擎。
> **守鐵則**：全部用 **DOM overlay + canvas 繪製 + Web Audio（`src/sfx.js`）**，零外部資源；粒子硬上限+回收；`node --check` 過、無頭 0 error。
> 下面給**可直接開工的分鏡/時序**。秒數為（建議值），可微調；**任何一步都能一鍵跳過（skip）**（尊重親子玩家的時間，也是健康設計）。

### 2.1 結算揭曉總時序（勝利，約 4.5 秒可全跳過）

> 記號：`t=` 為進入結算後的秒數；「叮/噹/號角」對應 `__sfx` 音效鍵（新增純程序化音，不加外部檔）。

```
t=0.00  勝利大字橫幅「棲地復原！」由中央 scale 0.6→1.05→1.0 彈入（squash&stretch）
        ＋金色勝利號角（低→高滑音）＋螢幕四角金色粒子小噴發（上限 60，回收）
        [失敗版：灰暗大字「棲地失守…」下沉淡入，無粒子，短促低音]

t=0.40  記分板卡片由下往上滑入（ease-out-back），列出本隊各守護者列（見 §2.3 星球員）
        每張卡「啪」落位配一個輕「噠」音（音高隨列序遞升 → J-19 上升音階）

t=1.00  ★ 本場守護之星（MVP）那一列高亮：放大 1.15、羽冠/桂冠光暈亮起、星光粒子
        ＋一聲較亮的「叮—」（比其他列高八度）

t=1.40  獎勵逐項「飛入」對應欄位（一件一件，間隔 0.25s，各配「叮」）：
          ①保育值 +N  ②XP +N  ③（若有）金幣/通行證進度
        每個獎勵 icon 從螢幕中央拋物線飛到左上對應徽章，落點時徽章 squash 一下

t=1.90  【保育之路】進度條登場：見 §2.2 逐格跳 + 里程碑演出（主秀，約 1.5~2.5s）

t≈3.9   若本場觸發里程碑解鎖 → 全螢幕短暫金光 + 「🔓 已解鎖：○○（守護者/服裝）」牌匾滑入
        ＋解鎖號角；否則跳過此段

t≈4.3   底部出現行動鈕：「↩ 再守一場」（主，大、發光）／「回大廳」／（連線）「回到小隊」
        ＋若掉落補給箱 → 補給箱在鈕上方彈跳+紅點（引導到 §3.3 開箱，見 R-BS-02）

任意時刻   點畫面任一處 = 快速推進到結尾（所有數字瞬間到位、動畫略過）→ 尊重時間
```

### 2.2 保育值 count-up + 進度條 + 里程碑（R-BS-01 的核心分鏡）

> 這是把 Brawl Stars「Trophy Road 揭曉」的**節奏**搬過來，主題原創（保育之路）。用 `__getEco / __conservationLevel`（SYSTEMS §A.3），**不改鍵名**。

**A. 數字逐格跳（count-up）**
- 從「戰前值」跳到「戰後值」，用 **ease-out** 緩動：**前段快、末段慢**（建議 total 0.8~1.2s；<10 點就短一點）。
- 每跳一次配一個很輕的「嗒」（音量小、音高隨進度**微升** → 情緒往上堆，J-19）。
- 數字本體每跳一下做極輕微 scale bounce（1.0→1.06→1.0），別過頭。

**B. 進度條充能到里程碑**
- 進度條 = 距離「下一個保育里程碑」（下一隻可解鎖守護者 / 下一件服裝 / 下一保育等級）。
- 條子從舊填充量**平滑充到**新填充量，與數字 count-up **同步**。
- **關鍵懸念手法**：若這一場會**跨過**里程碑，在「快到里程碑」時**刻意放慢最後 15%**（減速緩動），製造「就快了…就快了…」的張力 → **然後「鏘！」跨過**。

**C. 里程碑解鎖演出（跨過的瞬間）**
- 進度條到達里程碑點：該點**閃光**、進度條**短暫溢光/發亮**、一聲清亮「鏘—✨」。
- 若解鎖了具體內容：接 §2.1 t≈3.9 的「🔓 已解鎖」牌匾。
- 若只是保育等級+1：顯示「保育等級 ↑ Lv N」小牌 + 短號角。

**D. 沒跨里程碑時**：進度條就是「往前推一點」，仍給「差 X 保育值就解鎖○○」的**文字誘因**（把下一個目標種進玩家心裡 → 召回動機）。

### 2.3 星球員 / 貢獻（深化 R-BS-05 + R-BS-03）

> **為什麼**：MVP 高亮給勝者「被看見」的爽；**輸也顯示貢獻**給「下次會更好」的正回饋（避免只有懲罰）。
- 記分板每列：守護者頭像 + 名字 + **本場貢獻**（傷害 / 驅逐入侵種數 / 目標貢獻，如苗圃守護%）。
- 依綜合分選 **1 名「本場守護之星」**：放大、**羽冠/桂冠光暈**（台灣意象，避開 Supercell 皇冠）、星光粒子、較亮音效。
- **貢獻統計盡量本地/結束時算**（守 SYSTEMS §B.5 netcode 最小欄位，別每幀塞快照）。

### 2.4 演出設計的三條鐵律（親子健康版）
1. **一律可跳過**：任何揭曉都能一點略過。演出是禮物不是牢籠。
2. **輸也有正回饋**：顯示貢獻與「只升不降的 XP」，never 純懲罰。
3. **零外部資源**：所有光效/粒子 canvas 畫、所有聲音 Web Audio 程序合成（守鐵則）。

## 3. 健康的成長迴圈（每天想回來，且避免賭博化）

> 目標：串起 **每日任務 → 通行證 → 首領晉級 → 精通**，讓玩家**每天有一條進度在推進**，且**明確不踩賭博紅線**（我們是親子教育遊戲）。

### 3.1 為什麼會「想回來」（可用的正向心理學）

| 機制 | 底層原理 | 守土怎麼用（正向版） |
|---|---|---|
| **每日任務** | 操作制約（正增強）＋習慣養成（UCL：重複行為成習慣） | 已有 3 個（打贏/賺 150 保育值/擊敗首領）→ 領通行證點數。**保持「3 個、當天做得完」**，別讓任務變壓力。 |
| **目標設定 / 進度條** | 明確目標提升留存（Computers in Human Behavior）；「差一點就到」最拉人 | 保育之路、通行證軌、精通條——**永遠讓玩家看到「再一點就升級」**。 |
| **里程碑解鎖** | 完成感 / 勝任感（自我決定論 SDT） | 解鎖新守護者/服裝/**真實生態知識**（扣宗旨）。 |
| **精通（Mastery）** | 投入感 / 精熟動機 | 常玩某隻 → 解鎖該物種**真實圖鑑知識**（R-BS-10）。**用知識當獎勵，是我們相對商業遊戲的道德優勢。** |
| **首領晉級** | 能力進階 / 心流（難度隨能力上升） | 見習→大師，打贏晉級（SYSTEMS §A.4）。**階級是「能力證明」不是「付費階級」。** |

### 3.2 變動獎勵（variable reward）：用它的「好」，避開它的「毒」

> **神經科學事實**：不確定的獎勵讓多巴胺**噴發最猛**（大腦對「不可預測」最上心）。這也是 loot box 最黏、也最危險的原因。
> **我們的立場**：可以用「不確定性製造期待感」讓開箱好玩，但**必須把賭博的三個成癮鉤子拆掉**。

**變動獎勵的「健康用法」（准）**
- 補給箱**內容隨機**（哪件服裝/多少保育值）→ 製造「拆禮物」期待感。
- **蓄力揭曉**（按住 2/4/6/8 秒越久越好，R-BS-02）→ 期待感節奏，爽點在「揭曉那一刻」。
- 稀有度用**顏色/光效/音效**分級 → 揭曉的戲劇性。

### 3.3 賭博化紅線（禁止 — 一律不做）

> 以下每一條都是**設計紅線**。守土是親子教育遊戲，違反即否決。

1. **禁止真金購買隨機箱**：補給箱**只能靠玩（勝利/連勝/每日）獲得**，**永不**用真錢買箱、買抽數、買鑰匙。（我們無任何 IAP。）
2. **禁止「近失（near-miss）」操弄**：不做「差一點就傳說、可惜是普通」那種假裝差一點的動畫——那是賭場手法。揭曉就是誠實揭曉。
3. **禁止 FOMO / 損失焦慮壓迫**：
   - 每日任務**沒做完不懲罰**、streak **斷了不清空既有成果**（可有小連續獎勵，但**斷了只是沒有加碼，不倒扣**）。
   - 通行證**不設「限時逼你肝」的壓迫倒數**；賽季制若做，過期內容**改為之後仍可用其他方式取得**，不製造「錯過就永遠沒有」的焦慮。
4. **禁止付費強度（pay-to-win）**：所有戰力來源（等級/天賦/首領晉級）**只能靠玩取得**，服裝**純外觀**不影響數值（守 SYSTEMS 現況）。
5. **禁止掩蓋機率**：補給箱**公開稀有度掉率**（放在開箱介面說明），做「透明的隨機」而非「賭場的隨機」。（呼應各國對 loot box 揭露掉率的監管方向。）
6. **禁止「無限抽 / 保底鑽你錢」循環**：可有「連續沒中高稀有度就提升機率」的**溫和保底**（減少挫折），但**目的是體驗公平，不是誘導消費**（我們本就無消費）。
7. **尊重時間**：所有演出可跳過；不用「強制觀看動畫」拖時間。

### 3.4 每日回饋迴圈（把上面串成一天的節奏）

```
開 App → 大廳紅點提示「今天有 3 個任務 / 補給箱可領」（召回，不脅迫）
  → 打 1~2 場（每場 3~5 分，短局低摩擦）
     每場結算：保育之路逐格跳 + 里程碑懸念（§2）＝ 每場都有小爽點
  → 完成每日任務 → 領通行證點數（票券飛入 juice）
  → 用玩得到的箱子/點數 → 揭曉補給箱（期待感，健康隨機）→ 換純外觀服裝
  → 精通條 / 首領晉級 / 保育之路「差一點就到」→ 明天想回來把它推過去
  → 里程碑解鎖真實生態知識 → 扣回宗旨：玩＝認識台灣保育
```

**設計指北針一句話**：**用「期待感」與「勝任感」留住玩家，不用「焦慮」與「賭性」。**

## 4. 落地 Ticket（R-FEEL-01…）

> 依 `docs/PROCESS.md §3` 模板。難度 S(<半天)/M(1~2天)/L(需設計定案)。
> 一票否決鐵則：`node --check` 過、無頭 0 error、粒子上限+回收、單檔零外部資源、Canvas 純繪製、資料合約不改壞。
> **與第一輪銜接**：R-FEEL-03 是 **R-BS-01 的可開工細化版**（本文 §2.2）；R-FEEL-04 對應 **R-BS-03/05 星球員**（本文 §2.3）；R-FEEL-07/08 是 **R-BS-02 補給箱的健康設計約束**。

### R-FEEL-01 受擊方回饋（入侵種白閃 + squash + 微擊退）
- **使用者原話**（推導）：打中入侵種時，被打的那隻也要有明顯反應，打擊才有雙向重量。
- **意圖釐清**：入侵種被命中時 **白閃 2~3 幀 + 縱向 squash 一下 + 沿受擊方向微擊退**（純視覺，不改判定/血量公式）。對應手感清單 J-04/J-05。
- **對應系統**：對戰 | 美術/打擊感
- **驗收條件**：
  - [ ] 入侵種受擊白閃/squash/微擊退（純繪製，不改 `meleeHit` 判定與傷害）
  - [ ] 首領受擊也有（幅度更小，避免大位移穿牆）
  - [ ] 粒子/位移有上限、`node --check` 過、無頭 0 error
- **預估難度**：S~M
- **鐵則影響**：不改屬性相剋/傷害公式；`drawCreatureTop` 只加視覺層
- **狀態**：待辦

### R-FEEL-02 守護者出招 anticipation + follow-through + lunge
- **使用者原話**（推導）：守護者的招式要有起手（前搖）和收招慣性，出手瞬間有前衝反衝。
- **意圖釐清**：普攻/技能加**1 格前搖（往後拉）→ 出手 lunge（前衝一點點）→ 收招慣性回位**。對應 J-07~J-09。用既有動畫相位，不改招式判定時序（或前搖極短以免手感變鈍）。
- **對應系統**：對戰 | 美術/打擊感
- **驗收條件**：
  - [ ] 出招前搖/lunge/收招（純視覺，攻擊判定命中窗不被拖慢到影響手感）
  - [ ] 連線一致（視覺相位本地算，不塞快照，守 §B.5）
  - [ ] 無頭 0 error
- **預估難度**：M
- **鐵則影響**：`drawCreatureTop` 加視覺；不改 `cd`/`spCd` 資料語意
- **狀態**：待辦

### R-FEEL-03 結算揭曉演出（保育之路 count-up + 里程碑懸念）★ = R-BS-01 開工版
- **使用者原話**（推導自 R-BS-01 + 本文 §2）：結算後保育值/XP 逐格跳，保育之路進度條充能，快到里程碑放慢製造懸念，跨過時閃光解鎖。
- **意圖釐清**：完整實作本文 **§2.1 總時序 + §2.2 count-up/進度條/里程碑**。ease-out count-up、音高隨進度微升、里程碑前放慢最後 15%、跨過「鏘✨」+解鎖牌匾。**全程可一點跳過**。用 `__getEco/__conservationLevel`，不改鍵名。
- **對應系統**：大廳/UI | 對戰（結算 `showOver`）
- **驗收條件**：
  - [ ] 保育值/XP 逐格 count-up（ease-out，可跳過）
  - [ ] 保育之路進度條同步充能；跨里程碑時放慢+閃光+解鎖演出
  - [ ] 沒跨里程碑也顯示「差 X 保育值解鎖○○」誘因文字
  - [ ] 音效走 `__sfx`（純程序化，音高遞升）；粒子上限+回收
  - [ ] Canvas/DOM 純繪製、單檔零外部資源、`node --check` 過、無頭 0 error
- **預估難度**：M
- **鐵則影響**：無違反（純繪製；沿用 eco/等級橋接鍵名不改）
- **狀態**：待辦（取代/細化 R-BS-01）

### R-FEEL-04 星球員 MVP + 貢獻記分板（= R-BS-03/05 細化）
- **使用者原話**（推導）：結算選一名 MVP 高亮，並列各守護者貢獻；輸也顯示。
- **意圖釐清**：記分板列**傷害/驅逐入侵種數/目標貢獻**，綜合分選「本場守護之星」（放大+羽冠光暈+星光+較亮音效，台灣意象非皇冠）。貢獻統計**本地/結束時算**，守 netcode 最小欄位。對應本文 §2.3。
- **對應系統**：對戰（結算）| 大廳/UI
- **驗收條件**：
  - [ ] 局內累積各角色傷害/擊殺（本地，不每幀塞快照）
  - [ ] 記分板 + MVP 高亮動畫（純繪製）
  - [ ] 輸也顯示貢獻（正回饋）
  - [ ] 連線僅結束時單次同步（或本地算），守 §B.5；無頭 0 error
- **預估難度**：M
- **鐵則影響**：netcode 快照最小化（`docs/SYSTEMS.md §B.5`）
- **狀態**：待辦

### R-FEEL-05 螢幕震動分級 + 命中 punch-in zoom
- **使用者原話**（推導）：震動要克制分級（普攻小、必殺中、首領擊破大），重擊時鏡頭猛推一下更爽。
- **意圖釐清**：把 screen shake 分 3 級 amplitude（隨機方向、easing 快速衰減 0.1~0.3s）；hit-stop 同幀對重擊/擊破加 **punch-in zoom 1~2% 再回**。對應 J-12/J-14。
- **對應系統**：美術/打擊感 | 對戰
- **驗收條件**：
  - [ ] 震動 3 級（普攻/必殺/首領擊破），easing 衰減、不長期抖
  - [ ] 重擊/擊破 punch-in zoom（不破壞跟隨鏡頭/座標換算）
  - [ ] 無頭 0 error
- **預估難度**：S~M
- **鐵則影響**：不破壞 world↔screen 座標換算與狀態機
- **狀態**：待辦

### R-FEEL-06 音效手感（pitch/volume 隨機化 + 上升音階）
- **使用者原話**（推導）：重複音效要略微變化不膩，連段/count-up 要有往上堆的音階。
- **意圖釐清**：`src/sfx.js` 對重複音做 **±5~15% pitch/音量 jitter**；combo 與結算 count-up 用**遞升音高**（J-17/J-19）。純程序化 Web Audio。
- **對應系統**：美術/打擊感（音效）
- **驗收條件**：
  - [ ] 重複音 pitch/vol jitter（不爆音、可在設定關）
  - [ ] combo/count-up 遞升音階
  - [ ] 零外部音檔（守鐵則）、無頭 0 error
- **預估難度**：S
- **鐵則影響**：無（Web Audio 純合成）
- **狀態**：待辦

### R-FEEL-07 復育補給箱・健康隨機約束（= R-BS-02 的道德規格）
- **使用者原話**（推導自本文 §3.2/3.3）：補給箱好玩但不能賭博化。
- **意圖釐清**：R-BS-02 開工前**先鎖死本文 §3.3 的紅線**：只靠玩獲得、無真金購買、公開掉率、無 near-miss、無 FOMO 壓迫、溫和保底、純外觀不影響戰力、可跳過。**這是 R-BS-02 的驗收前置條款。**
- **對應系統**：通行證/成長 | 大廳/UI
- **驗收條件**：
  - [ ] 補給箱僅由勝利/連勝/每日獲得（無 IAP 入口）
  - [ ] 開箱介面**公開稀有度掉率**
  - [ ] 無 near-miss 假動畫；揭曉誠實
  - [ ] 內容為保育值/純外觀服裝/解鎖碎片（不含戰力數值）
  - [ ] 蓄力揭曉可放開即結束（不強制拖時間）
- **預估難度**：S（規格約束，與 R-BS-02 實作合併）
- **鐵則影響**：無（設計紅線）；掉率鍵走 `shoutu_supply_*` 不改既有鍵
- **狀態**：待辦（R-BS-02 前置）

### R-FEEL-08 健康成長迴圈・反 FOMO 每日任務/通行證
- **使用者原話**（推導自本文 §3.1/3.3）：每天想回來，但不用焦慮逼玩家。
- **意圖釐清**：每日任務**沒做完不罰**；連續獎勵**斷了不倒扣**（只是沒加碼）；通行證**不設壓迫倒數**、過期內容改為仍可他法取得。把「差一點就到」的正向誘因（保育之路/精通/首領晉級）做足。對應本文 §3。
